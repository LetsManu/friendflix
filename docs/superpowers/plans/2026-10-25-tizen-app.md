# Samsung TV (Tizen) App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A FriendFlix app for Samsung TVs (Tizen 6.5+). It opens the server's TV mode, plays through Samsung's AVPlay player
behind the web player's own controls, and is built, signed and attached to releases by CI.

**Architecture:** The plan has two parts with a gate between them.

- **Part 1** ships everything the owner needs to run the phase-0 probe on the real TV:
  - the server accepting `client: 'tizen'`;
  - web detection and the probe;
  - the `tizen/app` and `tizen/probe` shells with the setup page;
  - signing in CI, the install scripts, the docs.
- **Gate:** the owner reports the probe line. Plan A or plan B is ruled and recorded in the ledger.
- **Part 2 (plan A):**
  - an AVPlay adapter that takes over an existing `<video>` element (instance properties and synthetic events), so
    `Player.svelte` changes very little;
  - the capability block;
  - the remote keys;
  - the player docs.
- If the gate rules plan B, Part 2 is replaced by a new task list written against spec §6 before any Part 2 work starts.

**Tech Stack:**
- SvelteKit/TypeScript (web), vitest and Playwright;
- Fastify/zod (backend);
- Tizen web app (`config.xml`, plain JS), Tizen CLI (`tizen package`, `sdb`);
- GitHub Actions, PowerShell and bash.

**Spec:** `docs/superpowers/specs/2026-10-25-tizen-app-design.md` (read it with this plan; § numbers refer to it).

## Global Constraints

- Target: Samsung TVs 2022+ (Tizen 6.5); `config.xml` requires version 6.5.
- The user-agent marker is ` FriendFlixTizen/<version>`. If the TV cannot set it, detection falls back to
  `typeof tizen !== 'undefined'` plus the `ff_app=tizen` query parameter on `/tv`. The marker grants no rights; it only switches
  on the AVPlay adapter, the keys and the capability block.
- Server address: `https://host[:port]` only (`http://` refused). `authOrigin` is accepted only as `https://host`. Stored in
  `localStorage` as `ff.server` and `ff.authOrigin`.
- Navigation is locked to the server origin and the auth origin (spec §3: `allow-navigation`, or enforcement in `index.html`;
  the chosen way is documented).
- The backend `clientCaps` allowlists are unchanged; only `client: 'tizen'` is added.
- Signing secrets: `TIZEN_AUTHOR_P12`, `TIZEN_AUTHOR_PASSWORD`, `TIZEN_DISTRIBUTOR_P12`, `TIZEN_DISTRIBUTOR_PASSWORD` (p12 as
  base64). Never echoed. Without them the job builds nothing and leaves a `::notice`.
- The `tizen-release` job is NOT in the `needs` of `publish` or `android-release`.
- Every downloaded tool (Tizen CLI) is pinned by exact version and SHA-256. Actions are pinned by commit SHA.
- Placeholder hosts only (`friend.example.com`, `auth.example.com`, `192.0.2.x`). Never "Netflix"/"Seerr" in user-facing text.
  No model names in commits or code.
- SPDX headers on new source files (`npm run spdx:check`).
- Commit trailers: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` and
  `Claude-Session: https://claude.ai/code/session_016uMXgkH3UD9V4XN9PEeaKN`.
- The web player outside the Tizen app must behave exactly as before. Every new code path is gated on `isTizenApp()`.

## Review Focus

1. The server address typed with the TV IME: spaces, uppercase, a trailing slash, a path, or `http://`. Expected: normalised to
   the origin, or a clear refusal. → Task 3 test `normalise_addresses`.
2. AVPlay never reaches `PLAYING` (it stays in `READY`/`IDLE`) and fires no error. Expected: the 15 s start timeout counts as a
   failure and the HLS/`<video>` fallback runs. → Task 6 test `start_timeout_falls_back`.
3. The app is suspended (Home key) while AVPlay is preparing, not playing. Expected: no crash and no double `prepareAsync`;
   playback resumes at the position on return. → Task 6 test `suspend_during_prepare`.
4. A media key arrives while no player is open (on the home screen). Expected: it is ignored, with no exception and no
   navigation. → Task 8 test `media_keys_outside_player_ignored`.
5. The release has no Tizen secrets, or a broken p12. Expected: a notice and a green run when the secrets are absent; a red
   `tizen-release` job that blocks nothing else when the p12 is broken. → Task 4: the workflow `if:` structure, checked by
   actionlint and by reading.

### Task 6: AVPlay adapter

**Files:**
- Create: `web/src/lib/tizen/avplay.ts`
- Test: `web/src/lib/tizen/avplay.test.ts` (with a `FakeAvPlay` in the test file that records calls, holds a state, and fires
  the listener callbacks on demand)

**Interfaces:**
- Produces:
  - `attachAvPlay(video: HTMLVideoElement, api: AvPlayApi, opts: { now?: () => number; startTimeoutMs?: number }):
    AvPlayHandle`.
  - From then on, the element's instance properties `src` (setter opens AVPlay; getter returns the last URL), `currentTime`
    (get from `getCurrentTime()/1000`; set → `seekTo(ms)`), `duration`, `paused`, `ended`, `readyState`, `seeking`, `muted`
    (→ `setMute`), `buffered` (a single range 0..current), `play()` (Promise), `pause()`, `canPlayType()` (returns
    `'probably'` for `application/vnd.apple.mpegurl` and video/mp4 so the player takes the native path without hls.js) and
    `load()` are served by AVPlay.
  - Synthetic events are dispatched on the element itself: `loadedmetadata`, `loadeddata`, `canplay`, `play`, `playing`,
    `pause`, `waiting` (buffering start), `timeupdate` (every 250 ms while playing), `seeking`, `seeked`, `ended`, `error`
    (with `video.error = { code, message }`).
  - `AvPlayHandle`:
    - `audioTracks(): { index: number; lang: string; label: string }[]`, `selectAudio(index: number): void`;
    - `suspend()`, `restore()`;
    - `fallback: 'none' | 'hls' | 'video'`;
    - `setRect(x, y, w, h)`;
    - `detach()` (closes AVPlay and restores the prototype behaviour by deleting the instance properties).
  - `AvPlayApi` is the subset of `webapis.avplay` used: `open`, `close`, `prepareAsync`, `play`, `pause`, `stop`, `seekTo`,
    `getCurrentTime`, `getDuration`, `getState`, `setListener`, `setDisplayRect`, `setDisplayMethod`, `getTotalTrackInfo`,
    `setSelectTrack`, `setStreamingProperty`, `setMute`, `suspend`, `restore`.
- Order on `src` set:
  - `open(url)`, `setListener`, `setDisplayMethod('PLAYER_DISPLAY_MODE_LETTER_BOX')`, `setDisplayRect(...)`;
  - for `.m3u8` URLs, `setStreamingProperty('ADAPTIVE_INFO', 'STARTBITRATE=HIGHEST')`;
  - `prepareAsync(ok, err)`; after ok, `loadedmetadata`/`loadeddata`/`canplay`.
- Fallback: on an error or a start timeout with `fallback === 'none'` and an HLS URL known (`opts.hlsUrl` set by the player via
  `handle.setHlsFallback(url)`), reopen with HLS at the current position (`fallback = 'hls'`). A second failure dispatches
  `error` and sets `fallback = 'video'`. The player then detaches and uses `<video>`/hls.js.

  - `audio_tracks_mapping` (`getTotalTrackInfo` → language from `extra_info` JSON) and `selectAudio`;
