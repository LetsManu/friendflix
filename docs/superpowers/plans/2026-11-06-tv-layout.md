# TV Layout Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** In TV mode, replace the top bar, hero and long detail page with a side-bar rail, a focus tile over the existing home rows, a scroll-free detail page with a button list and sub-screens, and a bottom panel for player menus.

**Architecture:** Everything is gated on `html.tv` (set in `web/src/routes/+layout.svelte`). Pure logic (rail key handling, focus-tile debounce and content, detail button list, player panel back order, row scroll target) lives in small `web/src/lib/tv/*.ts` modules with Vitest tests; Svelte components in `web/src/lib/tv/` render it. Home keeps its row composition in `routes/+page.svelte` (recommendation engine order unchanged); only the hero area and the row styling change in TV mode.

**Tech Stack:** SvelteKit + TypeScript, Vitest (`cd web && npx vitest run <file>`), Playwright (`npx playwright test -c e2e/playwright.config.ts <file> --project=desktop --trace off`), i18n dictionaries in `web/src/lib/i18n/locales/<lang>/*.ts`.

**Spec:** `docs/superpowers/specs/2026-11-06-tv-layout-design.md`

## Global Constraints

- TV mode only (`document.documentElement.classList.contains('tv')` / `:global(html.tv)` CSS). Desktop, phone, kids UI and admin render exactly as before.
- Own look; never "Netflix" in user-facing text; no other service's names or logos.
- Safe area 96 px left/right, 54 px top/bottom at 1080p (`5vw` / `5vh`).
- Body text ≥ 28 px at 1080p on TV; focus targets ≥ 54 px tall (detail/panel buttons 56 px).
- Exactly one focused element; focus = `transform: scale(1.08)` + 3 px accent ring (`var(--accent)`).
- Animate only `transform` and `opacity`; no `backdrop-filter` or `filter: blur` under `html.tv`.
- Everything reachable with arrows, OK (Enter) and Back (`isBackKey` from `#lib/spatial`).
- Reuse existing loads/components; no backend change.
- Every new string in all seven locales (de, en, pl, es, fr, it, tr). New keys go in a new `tv.ts` file per locale, registered in each locale's `index.ts`; reuse existing keys where they already say the right thing (`shell.nav.*`, `detail.*`, `player.*`).
- Recommendation engine: row order, `reco` tags (`recoTrack`) and `ReasonCaption` unchanged.
- Trailer preview on TV uses `#lib/preview` (`playPreview`/`stopPreview`, muted by default, `autoplayAllowed()` covers calm mode and reduced motion) and also honours `$prefs.hoverTrailers`, `document.hidden` and `navigator.connection?.saveData`. The detail "preview starts the title" countdown stays off on TV.

## Review Focus

1. A title without backdrop, logo, synopsis or reason (sparse library metadata) → focus tile and detail page still lay out cleanly (name text instead of logo, plain gradient instead of image, missing lines omitted). Test in Task 2 (`tileInfo` with a bare item) and Task 4 (`tvDetailButtons` for a bare movie).
2. Fast scrolling through a row → no trailer starts and the tile does not flicker; only the title rested on for 300 ms is shown, trailer only after 1.5 s. Test in Task 2 (debounce).
3. Back from deep inside (detail sub-screen, player panel) → steps back one level at a time and never skips to the rail or exits the app. Tests in Task 5 (sub-screen Back restores the button focus) and Task 6 (`panelBack` order).
4. Empty home (new server: no resume, no recs) → the focus tile shows the hero title, ▼ from the tile buttons still reaches the first non-empty row. e2e in Task 7.
5. Pointer (Magic Remote) users → hovering the rail opens it, hovering away closes it without stealing keyboard focus from the content. Test in Task 1 (`railKey` pointer events).
