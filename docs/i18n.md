# Mehrsprachigkeit (i18n)

FriendFlix spricht Deutsch, Englisch, Französisch, Spanisch, Italienisch, Türkisch und Polnisch.
Deutsch ist die Quelle aller Texte und die Rückfallsprache. Die Umsetzung kommt ohne Zusatzbibliothek aus:
ein kleiner Svelte-Store plus `Intl` (PluralRules, DateTimeFormat, NumberFormat, RelativeTimeFormat, ListFormat, DisplayNames).

## Welche Sprache gilt?

1. **Profil**: jede Person wählt ihre Sprache pro Profil (Einstellungen → Sprache, Fußzeile, „Mein FriendFlix → Sprache“).
   Gespeichert in den Profil-Einstellungen (`profile_prefs.data.language`).
2. **Instanz-Standard**: von einem Admin festgelegt (`app_settings` Schlüssel `default_language`).
3. **Deutsch**, solange nichts gespeichert ist.

Erste Nutzung:

- Ein Admin (Hauptprofil) wird beim ersten Besuch einmal nach der **Sprache der Instanz** gefragt (Deutsch vorausgewählt).
  Hat das Admin-Profil selbst noch keine Sprache, wird dieselbe Wahl auch dafür gespeichert.
- Jedes Profil ohne gespeicherte Sprache sieht beim ersten Login die Vollbild-Auswahl **„Sprache wählen“**.
  Vorausgewählt ist die Browsersprache (falls unterstützt), sonst der Instanz-Standard. „Später“ speichert den
  Instanz-Standard, damit die Frage nicht wiederkommt.

Der Browser merkt sich die zuletzt genutzte Sprache (`localStorage` `ff-locale`), damit die Oberfläche schon vor der
Antwort von `/api/me` in der richtigen Sprache erscheint. Ein Sprachwechsel lädt die Seite nicht neu; der Seiteninhalt
wird einmal neu aufgebaut (`{#key $locale}` im Layout), `<html lang>` folgt.

## Backend

| Endpunkt | Zweck |
| --- | --- |
| `GET /api/me` | `language` (wirksam: Profil → Instanz → `de`), `languageChosen` (Profil hat eine eigene Wahl), `defaultLanguage`, `defaultLanguageSet`, `suggestedLanguage` (aus `Accept-Language`, nur als Vorschlag) |
| `PUT /api/prefs/language` `{ language }` | setzt nur die Sprache des aktiven Profils (jedes Profil darf das) |
| `PUT /api/prefs` | das volle Einstellungsobjekt enthält `language` (`''` = nie gewählt); fehlt das Feld (ältere Tabs), bleibt die gespeicherte Sprache erhalten |
| `GET/PUT /api/admin/settings/language` `{ language }` | Instanz-Standard (Admin, CSRF, Audit `settings.language`) |

Erlaubte Codes: `de en fr es it tr pl` (`backend/src/i18n.ts`, `LANGUAGES`). Keine Migration nötig.

Deutsch wird mitgebündelt, alle anderen Sprachen werden bei Bedarf nachgeladen.

## Benutzung

In `.svelte` (reaktiv, wechselt sofort mit der Sprache):

```svelte
<script lang="ts">
  import { t } from '#lib/i18n';
</script>
<h1>{$t('account.settings.title')}</h1>
<button aria-label={$t('common.close')}>…</button>
<p>{$t('shell.mobile.forName', { name: who })}</p>
```

In `.ts` (nicht reaktiv; erst aufrufen, wenn der Text gebraucht wird, nie auf Modulebene):

```ts
import { tr } from '#lib/i18n';
error = tr('common.saveFailed');
```

Schlüssel sind typisiert (`TKey`): ein Tippfehler ist ein Fehler in `npm run typecheck`. Für Schlüssel, die erst zur
Laufzeit entstehen, gibt es `trDynamic(key)`; besser sind Konstanten vom Typ `TKey` (siehe `lib/menu.ts`).
Listen mit Beschriftungen speichern den **Schlüssel** und übersetzen beim Anzeigen (`{$t(label)}`).

### Platzhalter und Mehrzahl

- `{name}` wird durch den Parameter ersetzt; Zahlen werden passend formatiert (`1.234` / `1,234`).
  Unbekannte Platzhalter bleiben sichtbar stehen.
- Mehrzahl: der Wert ist ein Objekt mit Formen, ausgewählt über den Parameter `n` mit `Intl.PluralRules`:

```ts
meUnread: { one: 'Mein FriendFlix, {n} neue Benachrichtigung', other: 'Mein FriendFlix, {n} neue Benachrichtigungen' },
```

`other` ist Pflicht. Mögliche Formen: `zero` (für n = 0 in jeder Sprache, optional), `one`, `two`, `few`, `many`, `other`.
Polnisch braucht `one`, `few`, `many`, `other`; Türkisch nur `other` (und optional `one`).

### Formatierer (aktuelle Sprache, alles über `Intl`)

| Funktion | Beispiel de / en |
| --- | --- |
| `fmtDate(d, opts?)` | 12. Oktober 2026 / 12 October 2026 |
| `fmtDateTime(d, opts?)` | 12.10.2026, 18:05 / 12 Oct 2026, 18:05 |
| `fmtTime(d, opts?)` | 18:05 |
| `fmtNumber(n, opts?)` | 1.234,5 / 1,234.5 |
| `fmtRelative(d, now?)` | gestern, vor 3 Stunden / yesterday, 3 hours ago |
| `fmtDuration(sekunden)` | 1 Std. 52 Min. / 1 h 52 min (Muster in `common.duration`) |
| `fmtList(items)` | Deutsch, Englisch und Japanisch |
| `intlLocale()` | `de-DE`, `en-GB` … für eigene `toLocale…String`-Aufrufe |

Nie `'de-DE'` fest eintragen. Sprachnamen von Ton-/Untertitelspuren liefert `langLabel()` (`lib/langs.ts`) in der UI-Sprache.

### Text mit Auszeichnung

Texte dürfen `<b>…</b>`, `<kbd>…</kbd>` und `<a href="/intern">…</a>` enthalten, wenn sie mit
`<Rich text={$t('shell.help.deviceD')} onLink={…} />` (`#lib/i18n/Rich.svelte`) ausgegeben werden. Alles andere bleibt
reiner Text – eine Übersetzung kann kein HTML einschleusen. Kein `{@html}` für Übersetzungen.

## Neuen Text hinzufügen

1. Schlüssel in `locales/de/<bereich>.ts` anlegen (sprechende, verschachtelte Namen, z. B. `detail.cast.title`).
2. Im Code `$t('detail.cast.title')` bzw. `tr(…)` verwenden.
3. Englisch in `locales/en/<bereich>.ts` ergänzen (Prüfung: der Typ erlaubt nur existierende Schlüssel).
4. Andere Sprachen dürfen fehlen – dann erscheint Deutsch.

## Übersetzung korrigieren oder Sprache ergänzen

- Korrigieren: Text in `locales/<sprache>/<bereich>.ts` ändern. Platzhalter (`{name}`, `{n}`) unverändert lassen.
- Neue Sprache: Eintrag in `LOCALES` (`web/src/lib/i18n/index.ts`, Code, Eigenname, BCP-47-Tag), Lader in `LOADERS`,
  Ordner `locales/<code>/` (Kopie von `locales/fr/` als Vorlage), Code in `backend/src/i18n.ts` (`LANGUAGES`).

## Rückfallregeln

1. Text der aktuellen Sprache,
2. sonst Deutsch,
3. sonst der Schlüssel selbst (in Entwicklung und Tests mit Warnung `[i18n] missing key "…"` in der Konsole).

Fehlt eine Pluralform, wird `other` genommen. Kann ein Sprach-Chunk nicht geladen werden (offline, nicht im Cache),
bleibt die bisherige Sprache aktiv.
